一、这个游戏是怎么来的

小学期有门课要交大作业，我用 Python 的 pygame 写了个东西：一架飞机，星空背景，敌人从上往下掉，按住键一直打。素材是网上找的几张图，代码不到一千行，玩法现在看简陋得不行。

但那是我第一次把一个"我想玩的东西"真的做成能点开、能动、能死的程序。做完之后我老是想着它——如果敌人再多两种、如果弹幕再花一点、如果清完一堆怪还能打一个很大的 Boss，会是什么样。

后来学了 Unity，我就把那个 pygame 版本的骨架整个搬过来重写了一遍。所以《元素战机》严格说不是另起炉灶做的新游戏，是那个小作业的第二次生长。玩法的内核没变，还是躲弹幕、打敌人、过关，但外面套的东西全换了。

二、三个参照物

做的时候脑子里一直有三个游戏在当尺子。我说清楚哪儿搬了、哪儿没搬，免得看起来像硬凑。

元气骑士给的是关卡节奏。它一关就几个房间，清完怪走到头打 Boss，一局十几分钟，死得起也刷得动。我喜欢这种短平快，所以这边也是选关进去、三波杂兵、关底 Boss、打完结算。但它的地图是随机拼的，这块我没做——我是五张固定地图，随机只体现在刷怪和掉落上。

吸血鬼幸存者给的是局内成长。它最抓人的是那种"越打越肥"：怪一直往你身上撞，你一边跑一边捡一地东西，升级的时候三选一，一局之内从一把小刀变成满屏特效。我照这个思路做了掉道具和升级三选一。差别是它池子大、组合能爆炸，我这边卡池只有十几张，深度差得远。

原神给的是元素和美术。这块搬得最实。五个属性火冰水雷岩，攻防之间有倍率，克制打 1.5 到 2 倍；两边凑上还有反应名——融化、蒸发、超载、冻结、感电、超导，岩打谁都是结晶。这些规则和名字都是照原神来的。道具的名字也往那个调性上靠，烤鸡大餐、烈焰之羽、守护羽帽，一看就知道是哪边的风格。

至于为什么挑原神：我确实喜欢这个游戏。做作业的时候拿自己真喜欢的东西当素材，坚持做完的概率高很多。

三、玩起来是什么样

标题页按任意键，输名字进菜单，选关——熔岩裂谷、深海遗迹、雷鸣高塔、岩山废矿，前四关都通了会开无尽模式。进去打三波怪，Boss 登场，打完结算。

操作不复杂：WASD 走，方向键决定往哪边打，开火是自动的。这个我纠结过一阵，弹幕游戏让人一直按着空格手会很累，不如省下来。Q 和 R 切属性，F 放元素大招，升级的时候用 1/2/3 选卡，P 暂停，Esc 回菜单。

五个属性各有一个角色，造型、子弹、大招都不一样。路上敌人是有颜色的，你看到下一波是什么色，就该想想要不要换个人再上——这是我整套设计里最想让玩家动脑子的地方。

局外还有一点很轻的成长：通关解锁新关卡和新属性，存档记着最高分、玩家名、杀了多少怪、捡了多少道具，图鉴里能翻。我故意没做数值上的永久变强，怕新手和老手差距一拉开，后面几关就没法用同一套数值做了。

四、右下角那只哆啦A梦

每一关的右下角，固定站着一只哆啦A梦。

它不攻击，不挡路，就站着，还会一上一下地飘。你把怪清得差不多了，绕过去靠近它，它就从口袋里往外掏东西：一次掉三个不重复的道具，散在它周围，你去捡。每关只能薅一次，触发的时候屏幕上飘一句"叮咚~ 哆啦A梦的礼物!"，然后这次就没了。

放这个纯粹是私心。小时候看动画最想要的就是那个口袋，现在自己能造一个游戏了，就想在里面放一个真的能掏出东西的口袋。而且一局打下来全程绷着躲弹幕，右下角有个莫名其妙的东西杵在那儿，我觉得挺好玩的。

实现上它是个独立脚本，位置、大小、触发距离都在文件开头的四个常量里，想挪想改都是改一行的事。

五、几处技术上的取舍

固定步长。pygame 那版我是拿"这一帧过了多久"去乘速度的，机器一卡，飞机就瞬移穿墙。Unity 这版把逻辑全锁在固定时间步里跑，不管画面多少帧，逻辑每 1/60 秒走一次。写起来麻烦一些，但手感稳了，也不会出现"好机器跑得飞快、笔记本慢动作"这种事。

碰撞没用物理引擎。场上同时有几百个东西在飞，挂 Rigidbody2D 让物理系统去算，性能反而更差，还得处理一堆我根本不需要的物理反应。所以自己写了矩形相交判定，玩家、敌人、子弹、掉落物都登记在一个列表里，每帧两两比一遍。听着很朴素，但几百个对象实测完全够用。

Boss 是三段状态机。血量掉到 66% 和 33% 各切一次阶段，每个阶段有自己的射击间隔、环形弹数量，还会加落雷和冲锋。三个阶段写成三份配置，切换只改参数不换代码，以后想加第四阶段就是加一份配置的事。

界面全是代码画的，一个 Prefab 都没拖。一开始当然用拖的，问题是一换分辨率就全乱，血条跑到屏幕外面这种事发生过不止一次。后来把整个 HUD 改成运行时按锚点生成，写了个小函数专门管定位。代价是改界面得改代码、看不到实时效果；好处是窗口随便拉，元素都跟着走。

六、三个印象最深的坑

第一个，"能跑"和"看起来能跑"不是一回事。第一次在命令行打包，Unity 直接退了，日志里一句有用的都没有。折腾了很久才发现不是构建的问题：工程放在带中文的路径下，路径参数传进去被吃掉了，Unity 拿到的是个不存在的目录，二话不说就退。换纯英文路径一试就通。

第二个，高刷屏把按键吃了。有段时间按 F 放大招经常没反应，我一度以为是键盘坏了。后来才想明白：逻辑跑在固定步长里，144Hz 的屏幕上有些帧压根不执行逻辑，我在逻辑里读"这一帧有没有按下 F"，那一帧就被永久跳过了。改法是按键在真实帧里先记下来，等逻辑走到的时候再消费。改完就没再漏过。

第三个，自己给自己挖的键位冲突。有一版数字键既是切角色又是选卡，结果一升级想按 1 选卡，角色跟着换了，能量还清了零。查了半天才反应过来是同一组键干了两件事。现在切属性改成 Q/R，数字键专给选卡。

七、关于素材

游戏里的角色、敌人、地图、头像，都是拿原神的图改的二创版本，我做了裁剪、换色、重新组合，没有直接搬原始素材。道具名和元素反应名也是致敬。

这套东西只用于课程作业和这次的面试展示，不商用、不发布。如果社团这边有要求，我可以换成自己画的占位图，程序不用动。

程序里真正用代码生成的只有子弹、血条、光环、对话框这类纯几何图形，美术主体还是上面那些图。

八、还没做好的

不吹，这几条我自己清楚：

地图不随机，五张图打完就没了，重复可玩性全靠难度和掉落撑着，不靠地形。

卡池太浅，十几张，一两局就能把能见到的都见一遍，长期玩会腻。

敌人 AI 很朴素，基本是朝玩家直飞、偶尔变向，没有绕后、包夹这些。

碰撞是两两遍历，对象上千会掉帧。正确做法是加空间网格分区，我知道该怎么改，但没来得及。

无尽模式只有一张图在循环，本来打算每十波换一次场景。

九、怎么跑起来

解压 zip，双击 YuansuPlan.exe，不用装任何东西。Windows 10 / 11，64 位。

杀毒软件可能报毒，因为这是个没签名的小众 exe，加白名单就行。还有一点，别只把 exe 单独拎出来，它旁边的 YuansuPlan_Data 文件夹里是全部资源，缺了打不开。

存档在 C:\Users\你的用户名\AppData\LocalLow\DefaultCompany\YuansuPlan，一个 json 文件，删了就重置。
